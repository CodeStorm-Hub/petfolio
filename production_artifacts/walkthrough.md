### 3. Database Optimization & Lag Reduction

To prevent network loops and UI frame-drops, the following repositories were rigorously optimized against the Supabase schema using clean declarative selections:

- `health_repository.dart`
- `pet_care_repository.dart`
- `social_repository.dart`
- `marketplace/data/repositories/*.dart` (all shop/order/product models)
- `admin_repository.dart`
- `pet_repository.dart`

**Key Enhancements Implemented:**
- **Stripped `select('*')`:** Removed heavy generic payload selections across the codebase and replaced them with explicit scalar selection strings (e.g. `select('id, name, bio...')`).
- **Inner Joins for N+1 Queries:** For relational payloads such as posts and their attached pets or authors, applied the `!inner` directive on Postgres joins to aggregate models within the remote instance natively rather than relying on sequential downstream loops.
- **Isolate Threading:** Forced the decoding arrays generated by large collection reads (`toList()`) into independent background isolates (`await Isolate.run(() => ...)`) to entirely shield the main thread from decoding locks.

### 4. Application Shell & State Preservation

The primary application navigation logic was entirely redesigned to improve layout performance and preserve tab-specific memory state:
- **`StatefulShellRoute` Migration:** The top-level `go_router` logic inside [router.dart](file:///g:/GitHub/petfolio/lib/core/router.dart) was upgraded to `StatefulShellRoute.indexedStack`. This encapsulates each tab (Pets, Care, Social, Match, Market) within an `IndexedStack`, guaranteeing no state destruction during screen transitions.
- **`SafeArea` Constraints:** We implemented explicit `SafeArea(bottom: false)` wrappers for the primary tab scaffolding to inherently defend against hardware notch intersections across iOS and Android while preserving the custom floating behavior.
- **Sliding Focus Window:** Built a custom animated `Stack` layer inside `_FloatingNav`. Instead of updating each tab independently, a unified `AnimatedAlign` layout smoothly translates the focus background horizontally to the newly requested index using an accelerated `Curves.easeInOut` function constrained to exactly 200ms.

### 2. [TailWagLoader](file:///g:/GitHub/petfolio/lib/core/widgets/tail_wag_loader.dart)
Constructed the animated loading state. The entire loader is sealed inside a `RepaintBoundary` to prevent rendering leakage up the widget tree.
- Uses a tightly scoped `AnimatedBuilder` that wraps *only* the wagging tail section.
- Prevents sibling invalidations for the Head, Body, Eye, and Ear models.
- Integrates native rotation constraints mapping `CurvedAnimation` dynamically to `-0.2` through `0.8` radians, oscillating infinitely via an `AnimationController` utilizing `.repeat(reverse: true)`.

### 3. [ReactionBurst](file:///g:/GitHub/petfolio/lib/core/widgets/reaction_burst.dart)
Wrote a declarative overlay layer driven by the `flutter_animate` physics engine instead of manually ticking state mechanisms.
- Dispatched floating components mapping `ReactionItem` origins via explicit bezier curves.
- Applies `.fadeIn()`, `.moveY(end: -60)`, `.moveX()`, `.rotate()`, and `.fadeOut()` chained asynchronously. 
- Guaranteed clean resource disposal without lingering timer memory leaks.
